VPN을 켜면 모든 트래픽이 암호화된다고 생각하기 쉽지만, 주소 창에 사이트 이름을 입력할 때마다 발생하는 DNS 요청은 별도로 새어나갈 수 있습니다. 이걸 "DNS 유출"이라고 부릅니다. 직접 확인하는 방법과 발견됐을 때 무엇을 해야 하는지 정리했습니다.

![DNS 요청은 VPN 터널 밖으로 새어나갈 수 있습니다](/info/images/dns-leak-test-guide/hero.png)

## DNS 유출이 정확히 뭘까

브라우저에 `google.com`을 입력하면, 실제 접속 전에 그 도메인이 어떤 IP 주소인지 먼저 물어보는 DNS 요청이 발생합니다. VPN이 제대로 동작하면 이 요청도 암호화된 터널을 통해 VPN 서버의 DNS로 전달됩니다. 그런데 운영체제 설정이나 VPN 앱의 결함으로 인해 이 요청만 기존 인터넷 회선(통신사 DNS)으로 그대로 빠져나가는 경우가 있습니다. 이러면 접속하는 웹사이트 목록이 통신사나 네트워크 관리자에게 그대로 노출됩니다. IP 주소는 VPN으로 가려졌는데, 방문 기록은 가려지지 않는 반쪽짜리 보호가 되는 셈입니다.

## 직접 확인하는 방법

1. VPN을 완전히 끈 상태에서 DNS 유출 테스트를 제공하는 웹사이트에 접속해 표시되는 DNS 서버 정보를 기록해둡니다. 보통 가입한 통신사 이름이 나옵니다.
2. VPN을 켜고 원하는 서버에 연결한 뒤, 같은 사이트를 새로고침합니다.
3. 이번에는 DNS 서버가 통신사가 아니라 VPN 업체 소속으로 바뀌어 있어야 정상입니다. 여전히 통신사 이름이 보인다면 유출입니다.
4. 서버를 바꿔가며 2~3개 서버에서 반복 확인하면 특정 서버만의 문제인지 앱 전체의 문제인지 구분됩니다.

각 VPN 업체들은 자사 사이트에서 이 테스트 도구를 직접 제공하기도 합니다. 예를 들어 [ExpressVPN의 DNS 유출 테스트 페이지](https://www.expressvpn.com/dns-leak-test)에서도 같은 방식으로 확인할 수 있습니다.

## 유출이 확인됐다면

![유출 발견 시 확인 순서](/info/images/dns-leak-test-guide/detail.png)

- VPN 앱 설정에서 "DNS 유출 방지" 또는 "커스텀 DNS 강제 사용" 옵션이 켜져 있는지 확인합니다.
- 윈도우 10/11의 경우 "스마트 다중 홈 이름 확인" 기능이 여러 네트워크 인터페이스 중 더 빠른 응답을 주는 DNS로 임의로 요청을 보내는 경우가 있어, VPN과 충돌할 수 있습니다.
- 킬스위치 기능이 있는 앱이라면 켜두는 것이 근본적인 방지책입니다. 킬스위치가 정확히 뭘 막아주는지는 [VPN 킬스위치란 무엇인가](/info/kill-switch-explained/)에서 다뤘습니다.
- IPv6를 쓰는 네트워크인데 VPN이 IPv4만 터널링한다면, IPv6 경로로 유출이 생길 수 있습니다. 앱에 IPv6 차단 옵션이 있다면 켜두는 것이 안전합니다.

## WebRTC 유출도 함께 확인하세요

DNS 유출과 자주 함께 언급되는 것이 WebRTC 유출입니다. 화상회의나 실시간 통화 기능을 지원하는 브라우저 기술(WebRTC)이 VPN 터널과 무관하게 실제 IP를 노출시키는 경우가 있습니다. 대부분의 DNS 유출 테스트 사이트는 WebRTC 유출도 함께 검사해주므로, 결과 페이지에서 이 항목도 같이 확인하는 것이 좋습니다. 유출이 확인되면 브라우저 설정이나 확장 프로그램으로 WebRTC 자체를 비활성화할 수 있습니다.

## 모바일에서도 똑같이 확인해야 합니다

DNS 유출은 PC보다 모바일에서 오히려 더 흔하게 발생합니다. 안드로이드는 제조사마다 배터리 최적화 정책이 달라, VPN 앱이 백그라운드에서 강제 종료되면서 DNS 요청만 원래 경로로 새어나가는 경우가 있습니다. 모바일 브라우저로 같은 테스트 사이트에 접속해 PC와 마찬가지로 확인해보는 것이 안전합니다. 특히 배터리 절약 모드가 강하게 설정된 기기라면 이 문제가 더 자주 발생할 수 있습니다.

## 공용 와이파이에서는 더 중요합니다

집이나 회사망보다 카페·공항 같은 공용 와이파이에서는 DNS 유출의 위험도가 더 큽니다. 같은 네트워크의 다른 사용자나 관리자가 트래픽을 들여다볼 가능성이 원천적으로 더 높기 때문입니다. 공용 와이파이 사용 시 일반적으로 주의할 점은 [공용 와이파이 안전하게 쓰는 법](/info/public-wifi-safety/)에서 정리했습니다.

## 커스텀 DNS를 직접 지정하는 방법도 있습니다

VPN 앱 자체의 DNS 유출 방지 기능과 별개로, 운영체제 네트워크 설정에서 신뢰할 수 있는 공개 DNS 서버(Cloudflare의 1.1.1.1, Google의 8.8.8.8 등)를 직접 지정하는 방법도 있습니다. 다만 이 방식은 VPN 터널 안에서 DNS 요청이 실제로 그 서버로 라우팅되는지까지 확인해야 의미가 있습니다. 단순히 DNS 주소만 바꾸고 VPN 터널 밖으로 요청이 새는 근본 문제를 해결하지 않으면, 겉보기만 바뀌고 실제 유출은 그대로일 수 있습니다. 이 방법을 쓴 뒤에도 반드시 테스트 사이트로 재확인하는 것이 안전합니다.

## 국내 인터넷 이용자 보호 관련 참고 자료

개인정보가 의도치 않게 노출되는 일반적인 위험과 예방 수칙은 [한국인터넷진흥원(KISA)](https://www.boho.or.kr)의 이용자 보호 자료에서도 확인할 수 있습니다. DNS 유출처럼 기술적으로 눈에 잘 띄지 않는 문제일수록, 정기적으로 점검하는 습관 자체가 가장 효과적인 예방책입니다.

## 얼마나 자주 확인해야 할까

한 번 확인했다고 영구히 안전한 것은 아닙니다. VPN 앱을 업데이트했거나, 운영체제를 업데이트했거나, 새 와이파이 네트워크에 처음 연결했을 때는 다시 확인하는 것이 안전합니다. 특히 운영체제 대규모 업데이트 이후에는 네트워크 관련 설정이 초기화되면서 DNS 유출 방지 옵션이 꺼진 채로 돌아오는 경우가 실제로 있습니다. 매번 확인하기 번거롭다면, 최소한 VPN을 새로 설치했을 때와 운영체제를 업데이트한 직후 두 시점만큼은 습관적으로 확인하는 것을 권합니다.

## 라우터에 VPN을 올려둔 경우는 더 신경 써야 합니다

공유기 자체에 VPN을 설정해 집 안의 모든 기기를 한 번에 보호하는 방식을 쓰고 있다면, DNS 유출 테스트도 라우터를 거치는 각 기기에서 개별적으로 확인하는 것이 안전합니다. 라우터 설정이 정상이어도 특정 기기의 개별 네트워크 설정(수동으로 지정한 DNS 서버 등)이 우선 적용되어 그 기기만 유출되는 경우가 있기 때문입니다. 공유기에 VPN을 설정하는 방법 자체는 [공유기에 VPN 설정하는 법](/info/router-vpn-setup-guide/)에서 다뤘습니다.

## 정리

DNS 유출 테스트는 브라우저와 테스트 사이트만 있으면 5분이면 끝나는 점검입니다. VPN을 새로 설치했거나 서버를 자주 바꾸는 편이라면 한 번씩 확인해보는 습관을 들이는 것이 좋습니다. "연결됨"이라는 표시만 믿기보다, 직접 눈으로 확인하는 것이 확실합니다.
